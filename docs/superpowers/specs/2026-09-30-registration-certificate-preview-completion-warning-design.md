# 報名管理證書預覽與結訓警告設計

## 目標

讓測驗通過後已自動產製、正等待寄送的證書可在報名管理列表直接預覽；並在單筆與批次手動標記「已結訓」前，明確提示仍未完成的 Woo 關聯作業。

## 範圍與既有流程

`TPMA_CR_Certificate_Service::record_quiz_pass()` 已會在測驗通過時呼叫發證流程。流程配置正式證書編號、產製 PDF，並把尚未寄出的報名狀態設為 `cert_ready`（待寄證）。本次不改變該自動產製流程。

報名列表 API 已帶回證書流水號、產製／寄送時間與狀態；證書管理 REST API 已提供受管理權限保護的 PDF 串流端點。本次會將兩者接到報名管理前端，不新增公開檔案 URL。

## 證書預覽

- 僅當報名狀態是 `cert_ready`，且有已產製的證書 PDF 時，狀態列的「待寄證」會是可點擊連結。
- 點擊後以與收據相同的方式預先開啟新視窗，再以 REST 權限與 nonce 取得 PDF Blob 顯示。
- `completed`（已結訓）、`cancelled`（已取消）及其他狀態不提供證書預覽；需要調閱時由既有證書管理後台處理。
- 無檔案或載入失敗時保留明確錯誤訊息，並關閉預先開啟的空白視窗。

## 狀態列顯示

- 當報名狀態為 `completed` 或 `cancelled`，僅顯示報名主狀態；付款、收據、證書與測驗標籤一律不顯示。
- 其他狀態維持既有付款、報名、收據與測驗標籤規則；`cert_ready` 的主狀態標籤依上述條件成為證書預覽入口。

## 手動結訓警告

警告只在手動把報名狀態改為 `completed` 時觸發，適用單筆儲存與批次狀態更新，並只檢查有有效 Woo 訂單 ID 的報名。沒有 Woo 關聯的舊資料完全略過。

每筆符合檢查範圍的報名，後端依現有收據主檔與證書主檔計算以下尚未完成原因：

- 收據尚未產製，或已產製但尚未寄出；
- 證書尚未產製，或已產製但尚未寄出；
- 測驗沒有成績；
- 測驗成績未達該課程既有的及格判定。

初次更新請求不會寫入資料，而會回傳每筆報名編號、姓名及原因。前端以可存取的確認視窗彙整顯示：管理者可取消，或明確選擇「仍要標記已結訓」。確認後以 `force_completion` 重新送出相同操作，後端才會執行更新。非 `completed` 狀態不需此二段確認。

批次操作由後端對選取 ID 整批計算，以避免目前列表資料過期；確認後仍沿用既有批次結果視窗呈現成功、略過與失敗項目。

## 錯誤處理與驗證

- REST 端維持既有 `manage_options` 權限檢查，且只接受既有白名單欄位／動作。
- `force_completion` 只用於略過警告並執行管理者已確認的手動結訓，不影響自動證書流程。
- 以 PHP 語法檢查、JavaScript 語法檢查、定向靜態搜尋與差異審閱驗證；完整互動仍需部署至 WordPress 測試站，涵蓋單筆、批次、舊資料與 PDF 預覽情境。
